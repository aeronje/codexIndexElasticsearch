# codexIndexElasticsearch

This repository is the appendix of [reindexArchiveSessionsForCodex](https://github.com/aeronje/reindexArchiveSessionsForCodex). It would be best to clone and explore that repository first before you begin cloning and installing this one.

This project is intentionally built for Codex archive retrieval. The parent
repository converts Codex rollout JSONL files into `codexIndex.csv`; this
repository indexes that CSV into a local Elasticsearch node, searches the Codex
sessions, and verifies selected results against the CSV source of truth.

The underlying provenance, indexing, and retrieval ideas can be adapted to
other datasets, but non-Codex use cases are outside this repository's supported
contract. Readers should understand the parent Codex archive workflow before
adapting the implementation elsewhere.

## Core rule

```text
codexIndex.csv = canonical Codex evidence
Elasticsearch = disposable search index
```

If `codexIndex.csv` and Elasticsearch disagree, the CSV wins and the index is
stale until rebuilt.

## Requirements

- Node.js 20 or newer
- Elasticsearch 9.x reachable locally through HTTP on `127.0.0.1`
- A `codexIndex.csv` generated by `reindexArchiveSessionsForCodex`

For a Debian-family host, review the installer without changing the machine:

```bash
bash scripts/elasticsearchSingleNodeInstallation.sh --dry-run
```

Then run it interactively:

```bash
bash scripts/elasticsearchSingleNodeInstallation.sh
```

The installer was tested for the project's Ubuntu 20.04 host. It installs
missing base packages and Node.js 24.x when Node.js 20+ is unavailable, verifies
Elastic's signing-key fingerprint, installs Elasticsearch 9.4.2, creates a
local-only single node with a 768 MiB heap, machine learning disabled, and
security auto-configuration disabled. It enables the service, backs up existing
Elasticsearch configuration, removes the package-generated TLS password entries
that are unused in this mode, and is safe to rerun. It does not silently perform
major-version upgrades.

The installer fails closed: it refuses to adopt an existing configuration that
does not contain its management marker, refuses an occupied port 9200, rolls the
keystore back if cleanup or metadata verification fails, and verifies the final
Elasticsearch product header, 9.x response, and `127.0.0.1`-only listener.
Linux may display that listener as `127.0.0.1`, `::1`, or the equivalent
IPv4-mapped IPv6 loopback `::ffff:127.0.0.1`; all other addresses are rejected.

This repository deliberately uses unauthenticated HTTP because Elasticsearch is
bound exclusively to `127.0.0.1`. Do not expose port 9200 to a LAN, tunnel,
container mapping, reverse proxy, or the public internet. Authentication and TLS
must be enabled before widening that trust boundary.

Other distributions and operating systems require review and adaptation. See
[the manual command reference](docs/manual-elasticsearch-installation.md) rather
than treating an untested platform as identical.

## Quick start

```bash
git clone https://github.com/aeronje/codexIndexElasticsearch.git
cd codexIndexElasticsearch
npm install
cp config.example.json config.json
```

Edit `config.json` and point `sourceCsv` to the canonical `codexIndex.csv`. No credentials,
environment variables, or certificate files are required for the installer’s
localhost-only mode.

Validate configuration and CSV without contacting Elasticsearch:

```bash
node src/cli.mjs config-check
```

Check Elasticsearch connectivity and compatibility:

```bash
node src/cli.mjs doctor
```

Import the CSV:

```bash
node src/cli.mjs import
```

Search:

```bash
node src/cli.mjs search "approved birthday leave"
node src/cli.mjs search "elasticsearch fuzzy matching" --fuzzy --limit 5
node src/cli.mjs search "birthday leave" --speaker assistant --from 2026-01-01 --show-query
```

Verify a selected hit using its `record_key`:

```bash
node src/cli.mjs verify --record-key <64-character-sha256>
```

## Commands

### `config-check`

Reads the local configuration and entire CSV, validates required headers, validates timestamps and messages, detects duplicate normalized records, and reports the CSV SHA-256 fingerprint. It does not contact Elasticsearch.

### `doctor`

Runs `config-check`, connects to Elasticsearch, confirms that the server is Elasticsearch 9.x, and reports cluster health.

### `import`

1. Reads and validates the configured CSV.
2. Creates a new versioned Elasticsearch index.
3. Bulk-indexes records with deterministic SHA-256 document IDs.
4. Verifies the Elasticsearch document count against the CSV.
5. Moves the configured alias to the verified generation.

Previous generated indices are retained for deliberate review. The importer never deletes an older working generation automatically.

### `status`

Compares the current CSV fingerprint and logical record count with metadata stored in the active Elasticsearch index.

Possible states:

- `verified`
- `stale`
- `not-indexed`

### `search`

Default behavior:

1. Search with all terms required.
2. If there are no hits, retry with 60% minimum term matching.
3. Return bounded results and neighboring rows from the same session.

Options:

```text
--limit N
--context N
--speaker VALUE
--role VALUE
--phase VALUE
--session VALUE
--from ISO_DATE
--to ISO_DATE
--fuzzy
--phrase
--any-term
--no-fallback
--show-query
```

### `verify`

Re-parses the canonical CSV, regenerates the stable record key, retrieves the matching Elasticsearch document, compares canonical fields, and checks the imported CSV fingerprint.

Possible states:

- `verified`
- `conflict`
- `missing-from-csv`
- `missing-from-elasticsearch`

## Configuration

Paths are resolved relative to `config.json` unless they are absolute.

```json
{
  "configVersion": 2,
  "sourceCsv": "/data/codexIndex.csv",
  "indexAlias": "codex-archive-sessions",
  "columns": {
    "timestamp": "timestamp",
    "sessionId": "sessionId",
    "turnId": "turnId",
    "speaker": "speaker",
    "role": "role",
    "phase": "phase",
    "message": "message",
    "fileNames": "fileNames",
    "urls": "urls",
    "sourceFile": "sourceFile"
  },
  "elasticsearch": {
    "node": "http://127.0.0.1:9200"
  },
  "search": {
    "defaultLimit": 10,
    "maximumLimit": 50,
    "defaultContextRows": 1
  }
}
```

Configuration version 2 is intentionally localhost-only and contains no
credential or TLS fields.

If migrating an older version 1 configuration, change `configVersion` to `2`
and replace the entire `elasticsearch` object with the single `node` setting
shown above.

## Privacy

The `.gitignore` excludes CSV files, local configuration, environment files,
SQLite files, logs, and generated databases. Codex archives can contain private
conversations, prompts, attachments, paths, and URLs. Do not commit personal
archives, retrieval packets, or generated Elasticsearch data.

## Development

```bash
npm test
npm run check
```

The test suite uses an in-memory fake Elasticsearch client. It does not install or start Elasticsearch.

The installer supports `--dry-run` and `--yes`. Run `--help` for details. The
tests never invoke APT, change system configuration, or start a service.

## Versioning

Update `manifest.json` whenever the configuration, record-key algorithm, index mapping, or CLI contract changes. A record-key or mapping change requires a new Elasticsearch index generation.
